# h3_dns_recordset (Resource)

One DNS record set (all records of a name and type) in an `h3_dns_zone`, like `aws_route53_record`. The whole set is replaced on every change. Record sets managed by the platform (LB/EIP/DB auto-records, ACME challenges) cannot be changed and are reported as conflicts.

## Example Usage

```terraform
resource "h3_dns_recordset" "www" {
  zone_id = h3_dns_zone.main.id
  name    = "www"
  type    = "A"
  ttl     = 300
  records = [h3_eip.web.ip_address]
}
```

## Schema

### Required

- `name` (String) Name relative to the zone: `www`, `@` for the apex, `*.app` for a wildcard, `_acme-challenge.www`
- `records` (Set of String) Record values. Host names may omit the trailing dot. TXT is plain text (long values are split by the service). MX `10 mail.example.com`, SRV `10 5 5060 sip.example.com`, CAA `0 issue "letsencrypt.org"`.
- `type` (String) A, AAAA, CNAME, MX, TXT, SRV, NS, CAA or ALIAS
- `zone_id` (String) Zone ID (`h3_dns_zone.<x>.id`)

### Optional

- `allow_overwrite` (Boolean) Take over an existing record set with the same name and type instead of failing
- `ttl` (Number) TTL in seconds (60-86400); default: the zone's default TTL

### Read-Only

- `etag` (String) Version (ETag) of the record set on the server. Updates and deletes are conditional on it (`If-Match`): a change made outside Terraform after the last refresh is never overwritten.
- `fqdn` (String) Fully qualified name
- `id` (String) `<zone_id>/<name>/<type>`

## Import

```shell
terraform import h3_dns_recordset.www <zone_id>/www/A
terraform import h3_dns_recordset.apex_mx <zone_id>/@/MX
```
