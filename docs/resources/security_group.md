# h3_security_group (Resource)

Security group of a project: stateful firewall rules (return traffic is allowed automatically) applied to the network
port of a VM. Every project has a group named `default` that allows all inbound and outbound traffic; it cannot be
created or deleted, but it can be imported and its rules edited (that is how you restrict access for VMs that use it).

Rules can be managed in one of two ways — **do not mix them on one group**:

- inline `rule` blocks: the resource owns the whole rule set, rules added elsewhere are removed on the next apply;
- no `rule` blocks + `h3_security_group_rule` resources: the group resource does not touch the rules.

Removing all `rule` blocks switches the group to the second mode and leaves its current rules in place.

Rule evaluation: a lower `priority` wins; among the groups of one VM the order is global (a `deny` in one group beats
an `allow` with a higher number in another group).

## Example Usage

```terraform
resource "h3_security_group" "web" {
  project_id = var.project_id
  name       = "web"

  rule {
    direction   = "ingress"
    protocol    = "tcp"
    port_from   = 443
    remote_cidr = "0.0.0.0/0"
  }
  rule {
    direction   = "egress"
    remote_cidr = "0.0.0.0/0"
  }
}
```

## Schema

### Required

- `name` (String) Name, unique in the project. `default` is reserved.

### Optional

- `description` (String) Description.
- `project_id` (String) Project ID (UUID). Defaults to the provider `project_id` (`H3_PROJECT_ID`). Changing it replaces the security group.
- `revoke_default_egress` (Boolean) Only on create without `rule` blocks: create the group with no rules at all instead of the platform default (allow all outbound, no inbound).
- `rule` (Block List) Inline rule. When at least one block is present the resource owns the **whole** rule set (rules added elsewhere are removed). Without blocks the rules are not managed, so the group can be combined with `h3_security_group_rule`. Do not mix both styles on one group. (see [below for nested schema](#nestedblock--rule))

### Read-Only

- `attached_count` (Number) Number of resources the group is attached to.
- `id` (String) Security group ID.
- `is_default` (Boolean) True for the project `default` group.
- `status` (String) `ACTIVE`, `SYNCING` or `ERROR`.

### Nested Schema for `rule`

Required:

- `direction` (String) `ingress` or `egress`.

Optional:

- `action` (String) `allow` (default) or `deny`.
- `description` (String) Free text, up to 255 characters.
- `port_from` (Number) First port (tcp/udp). Unset = all ports.
- `port_to` (Number) Last port (tcp/udp). Unset = `port_from`.
- `priority` (Number) 1..170, lower is evaluated first. Default 100.
- `protocol` (String) `all` (default), `tcp`, `udp` or `icmp`.
- `remote_cidr` (String) IPv4/IPv6 CIDR or address of the peer (`0.0.0.0/0`, `::/0` for any). Conflicts with `remote_security_group_id`.
- `remote_security_group_id` (String) Peer security group of the same project (may be this group).

## Import

```shell
terraform import h3_security_group.web <security_group_id>
# the project default group:
terraform import h3_security_group.default <default_group_id>
```

Destroying an imported `default` group only removes it from the state.
